# 03 · 权限设计（RBAC）

## 1. 角色模型

平台内置 4 个受保护角色（`roles.protected = TRUE`）：

| 角色 | 代码 | 说明 |
| --- | --- | --- |
| 系统管理员 | `SYS_ADMIN` | 用户/角色/权限管理与实验室登记；默认不读科研正文 |
| 实验室负责人 | `PI` | 审批立项/结项/资源预约，管理本实验室成员 |
| 科研项目负责人 | `PROJECT_LEADER` | 管理所负责项目的成员、任务、周报与成果审核 |
| 科研人员 | `RESEARCHER` | 承接任务、提交周报、申请资源、共享成果；注册默认角色 |

角色与业务身份分离：`roles` 决定「能力」，`lab_members` / `project_members` 决定「范围」。
注册只授予 `RESEARCHER` 且不加入任何实验室；PI 由管理员显式任命。

## 2. 授权判定公式

```text
allow = authenticated
      ∧ permissionExists(code)        -- @PreAuthorize 校验接口操作码
      ∧ scopeMatch(lab/project)       -- 应用服务按数据库关系校验实验室/项目范围
      ∧ ownerOrReviewer(subject)      -- 对象归属或审核关系
      ∧ stateGuard(currentState)      -- 状态机前置条件
```

- 权限码在校验中直接使用 `hasAuthority('xxx:yyy')`，**不硬编码角色名**；
- 服务层不信任请求中的 `userId / labId / projectId`，一律先按对象反查归属；
- 列表接口先按作用域过滤，再分页统计，不采用「查全表再前端过滤」。

## 4. 权限校验在代码中的位置

| 层次 | 位置 | 作用 |
| --- | --- | --- |
| 过滤器 | `shared/security/JwtAuthenticationFilter` + `identity/application/AccessTokenAuthenticator` | 校验令牌签名/过期/会话有效/账号状态/授权版本，装载当前权限集合 |
| 方法级 | `AdminUserController` 类上 `@PreAuthorize("hasAuthority('user:manage')")`、`AdminRoleController` 上 `hasAuthority('role:manage')` | 接口级强制校验，无权限直接 403，前端隐藏按钮不影响 |
| 服务级 | `UserAdminService` / `RoleAdminService` | 最后管理员保护、内置角色保护、角色引用检查、未知权限码校验 |
| 领域级 | `User.disable/changePassword` 递增 `auth_version`；`Role.ensureDeletable` 拒绝受保护角色 | 不变量由聚合自身维护 |

## 5. 动态生效机制

1. 管理员调用 `PUT /api/v1/admin/roles/{id}/permissions` 替换角色权限集合；
2. 下一次请求时 `AccessTokenAuthenticator` 重新查询 `users → roles → permissions`；
3. 同一个 access token 立即按新权限判定，**无需重新登录、无需重启、无需清缓存**。

对应测试：`RbacApiTest.permissionChangesTakeEffectImmediately`（新建角色 → 配额 0 → 动态授予 → 同一令牌看到新权限）。

## 6. 审计与限流的定位

- **审计**：`audit_events` 记录登录成功/失败、注册、退出、用户与角色变更、越权访问；字段仅包含脱敏元数据（动作、对象、结果、traceId、简短 metadata），不写正文与令牌。
- **独立事务**：拒绝类事件（登录失败、越权）通过 `REQUIRES_NEW` 写入，业务异常回滚不会带走证据，对应项目书「拒绝事件独立落库」。
- **限流**：登录失败按「规范化用户名 + 来源 IP」计数，阈值 5 次 / 10 分钟，超限返回 429；进程内实现便于本地演示，第三阶段改为 Redis 计数以支持多实例。

## 7. 防护负例清单

| 风险 | 防护 | 测试 |
| --- | --- | --- |
| 无权限调用管理接口 | 方法级 `@PreAuthorize` → 403 | `researcherCannotAccessAdminApi` |
| 越权修改他人数据 | 后续业务接口按对象归属校验（第一阶段为管理员专属接口） | 第二/三阶段补充 |
| 禁用账号后仍访问 | 会话吊销 + `enabled` 校验 + `auth_version` | `disablingUserInvalidatesExistingToken` |
| 退出后重放旧令牌 | 服务端会话吊销 | `logoutInvalidatesOldAccessToken` |
| 刷新令牌重放 | `used_at` 检测 + 会话族吊销 | `refreshRotatesTokenAndRevokesSessionOnReplay` |
| 锁死平台管理员 | 最后一个管理员保护 + 内置管理员角色必须保留 `user:manage`/`role:manage` | `lastAdminCannotBeDisabled`、`platformAdminPermissionsCannotBeRemoved` |
| 角色被引用仍删除 | 引用计数 → 409 | `roleInUseCannotBeDeleted` |
| 口令暴力枚举 | 按「用户名 + 来源 IP」固定窗口计数，5 次失败后 10 分钟内返回 429；成功登录清零 | `loginAttemptsAreThrottled`、`successfulLoginResetsThrottle` |
| Cookie 接口 CSRF | 刷新/退出校验 `Origin`/`Referer` 白名单；跨站 `Origin` 先被 CORS 拦截 | `refreshRejectsUntrustedOrigin`、`logoutRejectsUntrustedOrigin` |
| 数据库控制台外露 | `/h2-console` 仅在 `dev` profile 放行，生产 profile 直接 401 | `h2ConsoleIsNotPublicOutsideDev` |
| 越权与口令枚举无痕迹 | 拒绝事件用 `REQUIRES_NEW` 独立事务落库 | `deniedAccessIsAudited`、`failedLoginIsAudited` |
| 审计接口横向读取 | 平台管理员看全部；其他持有 `audit:read` 的角色只返回本人记录 | `auditQueryIsScopedForNonAdmin` |
