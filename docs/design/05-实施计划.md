## 3. 第二阶段计划（下一迭代）

1. 迁移 `V3__research_core.sql`：projects、project_members、project_reviews、tasks、task_submissions、reports、report_tasks（7 张表）。
2. 领域状态机：
   - 项目 `DRAFT → PENDING → ACTIVE → CLOSING → ARCHIVED`，`PENDING → REJECTED → DRAFT`，`CLOSING → ACTIVE`（退回）。
   - 任务 `TODO → IN_PROGRESS → SUBMITTED → DONE`，`SUBMITTED → RETURNED → IN_PROGRESS`，允许态 → `CANCELED`。
   - 周报 `DRAFT → SUBMITTED → APPROVED`，`SUBMITTED → RETURNED → DRAFT`。
3. 作用域与归属：项目负责人只能操作自己的项目；任务受派人本人才能开始/提交；审核人不得自审；越权返回 403/404。
4. 乐观锁：状态动作携带 `version`，冲突返回 409。
5. 进度计算：`100 × DONE 任务数 / 非取消任务数`，分母为 0 显示 0%。
6. 前端：项目列表/详情、任务看板、周报表单、PI 审批中心。

## 5. Git 与协作

- 分支策略：`main` 保护，功能分支 `feat/xxx` 合并；2 人组需 ≥ 3 个已合并 PR 且互相 review。
- 提交规范：`feat(module): ...`、`fix(module): ...`、`test(module): ...`、`docs: ...`，禁止 `update`/`fix`/`111`。
- 提交节奏：按阶段推进，跨至少 3 个自然周，避免最后 48 小时集中提交；不修改提交时间、不代提交。

## 6. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 环境无 Docker/PostgreSQL | 默认 H2 文件库保证可复现；生产 PostgreSQL 走 Flyway 同一脚本；第三阶段补 Compose |
| 范围膨胀 | P0 三实体（项目/任务/周报）优先，附加项按可验证证据逐项推进 |
| 越权漏洞 | 每个业务接口都有作用域 + 归属 + 状态三重校验与负例测试 |
| 并发状态不一致 | 乐观锁 `version` + 事务内状态守卫 + 冲突 409 |
| 密钥泄漏 | 仅环境变量注入；仓库无真实密钥；提供 `.env.example` |
| 交付时间 | 第一阶段已冻结可运行基线，后续按周迭代并保留回归测试 |
