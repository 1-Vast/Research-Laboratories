# 演示脚本（答辩用）

目标：**8 分钟内**走完「立项 → 审批 → 派活 → 交付 → 退回 → 重提 → 验收 → 周报 → 结项」全链路，并穿插 3 个越权负例。

演示的价值不在于"页面能点开"，而在于**每个动作背后有一条领域规则在拦人**。所以每步都配了一句"要讲什么"。

## 0. 前置检查（演示前 5 分钟做）

```bash
# 后端（终端 1）
cd backend
mvnw.cmd spring-boot:run -Dspring-boot.run.profiles=dev
# 等到日志出现：Started LabFlowApplication

# 前端（终端 2）
cd frontend
npm run dev
# 打开 http://localhost:5173
```

| 检查项 | 预期 |
| --- | --- |
| `curl http://localhost:8080/actuator/health` | `{"status":"UP"}` |
| 前端登录页可打开 | 无白屏、无控制台红色报错 |
| 数据库是干净状态 | 项目列表为空。若不是：停后端 → 删 `backend/data/` → 重启 |

> 数据是 H2 文件库，**演示前建议清一次**，否则上次演示的"已归档项目"会留在列表里，讲解时容易乱。

## 1. 演示账号

| 账号 | 密码 | 角色 | 在演示里干什么 |
| --- | --- | --- | --- |
| `leader_demo` | `Labflow@2026` | PROJECT_LEADER | 建项目、派任务、验收、申请结项 |
| `pi_demo` | `Labflow@2026` | PI | 审批立项、批准归档 |
| `researcher_a` | `Labflow@2026` | RESEARCHER | 接任务、提交交付、写周报 |
| `researcher_b` | `Labflow@2026` | RESEARCHER | **越权负例专用**（属实验室 B） |
| `admin_demo` | `Labflow@2026` | SYS_ADMIN | 用户/角色/审计（可选演示） |

演示时开 **两个浏览器窗口**（或一个正常 + 一个隐身），一个登 `leader_demo`，一个登 `pi_demo`，来回切换不用反复登录。

## 2. 主线（约 6 分钟）

### 第 1 步 · 负责人建项目（`leader_demo`）

**操作**：科研项目 → 新建 → 名称填「微流控芯片阻抗检测」→ 选实验室 A → 保存

**预期**：列表出现该项目，状态标签 `草稿`。

**要讲**：项目不是直接"生效"的，创建出来是草稿。草稿态下**不能派任务**，因为还没立项——下一步会当场验证这条规则。

### 第 2 步 · 草稿态派任务被拦（负例 ①）

**操作**：进入项目详情 → 任务看板 → 创建任务

**预期**：报错「当前状态不允许创建任务」，HTTP 409。

**要讲**：这条规则在**领域层**（`Project.assertActiveForTask()`），不在 Controller。所以不管从页面点、还是直接调接口，都拦得住。前端隐藏按钮只是体验，不是安全边界。

### 第 3 步 · 提交立项 → PI 审批

**操作 A**（`leader_demo`）：项目详情 → 提交立项 → 状态变 `待审批`
**操作 B**（切 `pi_demo`）：进入同一项目 → 审批通过 → 状态变 `进行中`

**要讲**：负责人自己**没有** `project:approve` 权限，所以页面上根本不出现"审批通过"按钮。即使手动构造请求，后端 `@PreAuthorize` 也会 403——这是"权限码决定能不能做"。

### 第 4 步 · 加成员 → 派任务

**操作**（`leader_demo`）：项目详情 → 成员区 → 按用户 ID 添加成员 → 任务看板 → 创建任务，受派人选 `researcher_a`

**预期**：任务出现在列表，状态 `待办`。

**要讲**：任务受派人**必须是项目成员**，否则报「受派人必须是该项目成员」。这条约束避免"把活派给局外人"，而局外人既看不到任务也无法提交。

### 第 5 步 · 受派人交付（`researcher_a`）

**操作**：我的任务 → 开始 → 提交交付（填「完成标定，误差 0.3%」）

**预期**：状态 `待验收`；项目详情里进度变成 0%（还没验收）。

**要讲**：只有**受派人本人**能开始和提交。负责人点"开始"会被 403——这不是前端藏了按钮，是服务层校验 `assigneeId == actorId`。

### 第 6 步 · 负责人退回，受派人重提（负例 ② 的反面）

**操作 A**（`leader_demo`）：任务 → 退回（填「请补误差曲线」）→ 状态变 `已退回`
**操作 B**（`researcher_a`）：任务 → 开始 → 提交交付（填「补充误差曲线后重新提交」）
**操作 C**（`leader_demo`）：任务 → 验收 → 状态变 `已完成`

**要讲**：退回不是"回到进行中"，而是一个独立状态 `已退回`，受派人必须**重新开工**才能再提交。每次提交都会生成一条**不可变交付快照**，旧内容不会被覆盖——这是"交付留痕"，答辩时可以展示提交历史里有两条记录。

### 第 7 步 · 周报（`researcher_a`）

**操作**：项目详情 → 周报 → 写周报 → 选本周 → 勾选刚才的任务 → 保存草稿 → 提交

**预期**：周起始日自动显示为本周**周一**；提交后正文输入框变只读。

**要讲**：两件事。① 周起始日由服务端归一到周一，因为 `(project_id, author_id, week_start)` 有唯一约束，不归一的话「周三」和「周一」会被当成两周，同一周能交两份。② 提交后正文只读，要改必须让负责人退回——避免"审核完偷偷改内容"。

### 第 8 步 · 周报审核（`pi_demo` 或负责人）

**操作**：周报 → 通过

**预期**：状态 `已通过`。

**要讲**：作者不能审核自己的周报，服务层拦 `SELF_REVIEW_FORBIDDEN`。

### 第 9 步 · 结项归档

**操作 A**（`leader_demo`）：项目详情 → 申请结项 → 状态 `待结项`
**操作 B**（`pi_demo`）：批准归档 → 状态 `已归档`

**要讲**：申请结项前会检查有没有未完成任务，有就 409 `OPEN_TASKS_EXIST`。归档后项目只读，不能再派任务。

## 3. 越权负例（约 1.5 分钟，这段最能加分）

### 负例 ③ · 跨实验室访问（`researcher_b`）

**操作**：登录 `researcher_b` → 直接访问 `http://localhost:5173/projects/{刚才的项目ID}`

**预期**：403，提示无项目成员权限。

**要讲**：`researcher_b` 属于实验室 B，该项目的实验室是 A。**实验室作用域**（`lab_members`）和**项目成员关系**（`project_members`）是两道独立闸门。注意 URL 里的 id 是猜得到的，所以后端必须按 id 反查归属再校验，不能信前端传的 `projectId`。

### 负例 ④ · 同周重复周报（`researcher_a`）

**操作**：同一项目、同一周，再写一份周报

**预期**：409 `DUPLICATE_REPORT_WEEK`。

**要讲**：服务层先预检，数据库唯一约束兜底。两层都有，是因为并发下预检可能同时通过。

### 负例 ⑤ · 过期版本号（可选，命令行演示）

```bash
curl -X POST http://localhost:8080/api/v1/projects/{id}/submit \
  -H "Authorization: Bearer <token>" \
  -H "Content-Type: application/json" \
  -d '{"version":0}'
```

**预期**：409 `VERSION_CONFLICT`。

**要讲**：两个人同时点"提交"，后到的那个会失败而不是覆盖前一个的结果。这是乐观锁，冲突让前端提示刷新，而不是静默丢更新。

## 4. 可选加分项

| 项 | 操作 | 讲解点 |
| --- | --- | --- |
| 审计留痕 | `admin_demo` → 审计日志 | 刚才的立项/审批/验收/越权尝试都有记录，且**不含正文与令牌** |
| 审计作用域 | 用 `pi_demo` 看审计日志 | 只能看到与本人相关的记录，不是全平台 |
| 动态权限 | `admin_demo` → 角色权限 → 给 RESEARCHER 勾上 `project:create` → 用 `researcher_a` **不重新登录**再建项目 | 权限每次请求从库里重载，改了立刻生效；JWT 里不带权限 |
| 退出即失效 | 退出登录后用旧 token 调 `/api/v1/me` | 401 `SESSION_REVOKED`，服务端吊销而不是前端删 token |

## 5. 兜底方案

前端万一出问题（端口占用、代理拦截、浏览器缓存），**立刻切 Swagger**，不影响讲解：

- Swagger UI：`http://localhost:8080/swagger-ui.html`
- 一键跑通全链路（不需要点页面）：

```bash
python scripts/e2e_smoke.py
```

输出 72 项 `PASS`，覆盖本项目所有主流程与负例。**这是最硬的兜底证据**：即使投影仪坏了，终端里也能证明链路是通的。

> 注意：如果机器上设了 `http_proxy`，本机请求可能被代理劫持成 502。脚本已内置绕过代理；手工用 `curl` 时加 `--noproxy '*'`。

## 7. 常见提问与回答要点

| 问题 | 回答要点 |
| --- | --- |
| 权限为什么不在前端判断？ | 前端隐藏按钮只影响体验，抓包直接调接口就绕过了。所有 `@PreAuthorize` 在服务端，越权负例有测试覆盖。 |
| 角色和实验室是什么关系？ | 角色决定"能做什么"（能力），`lab_members` / `project_members` 决定"在哪个范围做"（作用域）。两者分离，所以同一个 RESEARCHER 在 A 实验室能看项目、在 B 实验室看不到。 |
| 状态为什么不用一个 `status` 字段随便改？ | 通用 `PUT` 不接受 `status`，只能走 `/submit`、`/approve` 这类命令接口，迁移规则在聚合里。否则任何有更新权限的人都能把草稿直接改成已归档。 |
| 两个人同时操作会怎样？ | 乐观锁 `version`，后提交的拿 409，前端提示刷新，不会静默覆盖。 |
| 为什么退回要单独一个状态？ | 退回意味着"重新开工"，不是"继续干"。独立状态让进度统计、待办列表、通知都能准确区分。 |
| 交付快照为什么单独建表？ | 一列只能存最后一次，历史被覆盖就无法回答"第一次交了什么、为什么被退回"。 |
