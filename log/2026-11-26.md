### 2.5 任务工作流接口（B3）

| 层 | 新增内容 |
| --- | --- |
| 应用层 | `TaskService`（11 个用例）、5 个命令对象 |
| 接口层 | `TaskController`（11 个端点）、5 个请求 DTO、`TaskVo`、`TaskSubmissionVo` |

| 方法 | 路径 | 权限码 | 约束 |
| --- | --- | --- | --- |
| GET | `/api/v1/tasks/mine` | `task:read` | 只返回指派给自己的任务 |
| GET | `/api/v1/projects/{projectId}/tasks` | `task:read` | 项目成员 / 负责人 / 实验室 PI |
| POST | `/api/v1/projects/{projectId}/tasks` | `task:create` | 负责人 + 项目 ACTIVE + 受派人必须是成员 |
| GET/PUT/DELETE | `/api/v1/tasks/{id}` | `task:read` / `task:update` / `task:delete` | 由 taskId 反查项目再校验归属 |
| POST | `/tasks/{id}/start`、`/submit` | `task:start` / `task:submit` | 只有受派人本人 |
| POST | `/tasks/{id}/review` | `task:review` | 负责人 + 禁止自审 + 退回须写原因 |
| POST | `/tasks/{id}/cancel` | `task:update` | 已提交或已验收的任务不可取消 |
| GET | `/tasks/{id}/submissions` | `task:read` | 交付历史按提交号升序 |

设计要点：

1. **水平越权防护**：所有 `taskId` 端点都先 `findById → projectId → 校验项目成员关系`，不信任 URL 上的 projectId。改 taskId 拿别人项目的任务会得到 403。
2. **交付快照不覆盖**：`submit` 前取 `nextSubmissionNo`，退回后重提生成第 2 条记录，答辩可展示「第 1 次被打回、第 2 次通过」。
3. **验收回写快照**：`review` 除了迁移任务状态，还把最近一条 `SUBMITTED` 快照标记为 `APPROVED/RETURNED`，避免「任务已通过但交付记录仍待审」的数据矛盾。
4. **任务反向影响项目**：进度 = `DONE / (总数 - CANCELED)`；有未验收任务时申请结项返回 `OPEN_TASKS_EXIST`。

| 方法 | 路径 | 权限码 | 约束 |
| --- | --- | --- | --- |
| GET | `/api/v1/projects/{projectId}/reports` | `report:read` | 项目成员 / 负责人 / PI |
| POST | `/api/v1/projects/{projectId}/reports` | `report:create` | 必须是项目成员；同周唯一 |
| GET/PUT/DELETE | `/api/v1/reports/{id}` | `report:read` / `report:update` / `report:delete` | 改删仅作者本人；删除仅草稿 |
| POST | `/api/v1/reports/{id}/submit` | `report:submit` | 作者本人 + 版本号 |
| POST | `/api/v1/reports/{id}/review` | `report:review` | 负责人或 PI；禁止自审；退回须写意见 |

设计要点：

1. **周起始日归一**：传任意一天都会归一到该周周一，避免「同一周写两条」。
2. **唯一性双保险**：服务层 `existsWeek` 预检给出可读提示，数据库 `uq_reports_week` 兜底并发。
3. **提交后正文只读**：`Report.update` 只允许 DRAFT/RETURNED，审核对象不会被中途替换。
4. **跨项目任务拒绝关联**：`taskIds` 逐个校验 `task.projectId == report.projectId`，否则周报会混入别的项目进度。

## 3. 关键决策

1. **状态机放在聚合内**，不放在 Service：`Project.approve()` 之类方法自己判断前置状态与自审，Service 只负责作用域查询与事务。理由：答辩要能指认“领域规则在哪”，也是架构升级附加项的证据。
2. **作用域与角色分离**：系统角色（`PROJECT_LEADER`）只说明“具备能力”，`project_members` 才说明“在哪个项目里有效”。所有对象级接口先由 `taskId/reportId` 反查所属项目，再校验成员关系，避免只校验 URL 上的 `projectId`。
3. **不改 V2 种子脚本**：Flyway 校验和会冲突，所有种子修正走后续迁移。
4. **`project_reviews` 只增不改**：审批轨迹是答辩证据，允许更新会失去追溯意义。

### 6.3 冒烟过程中暴露的认知偏差

首次执行有 4 项失败，全部是**脚本对状态机的假设错了，不是代码错了**：

1. 以为任务退回后回到 `IN_PROGRESS`，实际领域模型是独立的 `RETURNED` 态（`TaskStatus` 有 6 个值：`TODO`/`IN_PROGRESS`/`SUBMITTED`/`DONE`/`RETURNED`/`CANCELED`）。
2. 以为退回后可直接重提，实际必须先 `start` 再次进入 `IN_PROGRESS`（`Task.start()` 允许 `TODO` 和 `RETURNED` 两个入口）。这是有意的：退回不是"继续干"，而是"重新开工"，版本号也随之中间多一次递增。
3. 以为 `GET /projects/{id}` 返回扁平项目对象，实际是 `{project, progress, members}` 聚合体——前端也是按这个结构取值的。
4. `TaskVo` 没有 `latestSubmissionNo` 字段，快照号只能从 `/tasks/{id}/submissions` 列表读。

> 这正是加这层冒烟的价值：前三条如果只靠单测，会一直"绿"下去，直到演示时前端拿到 `undefined`。

## 7. 契约走查发现并修复的数据丢失缺陷

浏览器 E2E 未做（`agent-browser` 未安装，装 Chromium 成本高），改用**契约走查**：把前端 30 个 API 函数的路径、请求体、字段消费逐一对照后端 57 个端点。结果全部路径匹配，但发现一处静默丢数据。

### 7.1 缺陷

`GET /projects/{id}/reports`（列表）里，`taskIds` 被硬编码成空数组：

```java
// 修复前
return ApiResponse.ok(result.map(report -> ResearchWebMapper.toReportVo(report, List.of())), ...);
```

前端 `ReportsView.startEdit()` 直接复用列表行：

```ts
form.taskIds = [...report.taskIds]   // 恒为空
```

于是**编辑一份已关联任务的草稿周报 → 保存 → 关联任务被清空**，且没有任何报错。列表接口的 `ReportVo` 声明了 `taskIds` 字段却永远返回空，属于契约说谎。

### 7.2 修复

按整页批量取回关联，而不是逐条查（避免 N+1）：

- 仓储端口新增 `Map<Long, List<Long>> findTaskIdsByReports(List<Long> reportIds)`
- 适配器用一次 `findByReportIdIn` + `groupingBy` 实现
- `ReportService.taskIdsOf(reportIds)` 暴露给接口层
- 控制器按页取一次，未关联的周报补 `List.of()`

### 7.3 回归保护

- `ReportApiTest.linksOwnTask` 增加列表断言：`$.data.items[0].taskIds[0]` 必须等于关联任务 id
- `scripts/e2e_smoke.py` 增加"列表回显关联任务"一项（现 72 项）

验证：

```text
mvn verify -> 258 个用例，0 失败
覆盖率 92.8%（2154/2321），门禁通过
e2e_smoke.py -> 通过 72 项，失败 0 项
```

### 7.4 另一个坑：本机请求被 HTTP 代理劫持

重跑冒烟时登录返回 502 `upstream connect failed ... 10061`。原因是环境里设了 `http_proxy`，`urllib` 把 `127.0.0.1` 也发给代理。脚本改为 `build_opener(ProxyHandler({}))` 显式绕过代理，并对非 JSON 错误体做了兜底，避免抛 `JSONDecodeError` 掩盖真实状态码。

> 这类问题在单测里永远不会出现（MockMvc 不经过网络栈），只有真跑 HTTP 才暴露。

## 9. 推送与 PR（已完成）

推送时的两个环境问题：

1. **代理**：本机 `http_proxy` 会让 git 在推送中途卡死（第一次尝试在 `feat-task-workflow` 上停了 12 分钟无进度）。而同一环境下 `curl --noproxy '*'` 直连一直正常，说明直连没问题。脚本改为 `git -c http.proxy= -c https.proxy=` 显式清空代理后，六个分支全部推完。
2. **git 不接受 MSYS 绝对路径**作为 `-C` 参数（`git -C /c/Users/...` 报 `cannot change to`），脚本内统一先 `cd` 到仓库根目录再用相对路径。

> 关于 token：前两次给的细粒度 PAT 都卡在 `Contents: Read`。定位方法是看 403 响应的 `x-accepted-github-permissions: contents=write`（GitHub 在说"我要这个权限，你没有"），再用 `GET /user/repos?affiliation=collaborator,owner` 确认 token 的仓库范围是否包含目标仓库——这两步能把"没加协作者""没选中仓库""权限没勾上"三种原因区分开，不必反复猜。
