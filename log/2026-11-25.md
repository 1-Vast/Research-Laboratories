## 3. 关键决策与理由

| 决策 | 理由 | 影响 |
| --- | --- | --- |
| 默认数据库用 H2 文件库，生产用 PostgreSQL | 本机无 Docker/PostgreSQL；H2 文件库数据落盘、重启不丢，且 DDL 保持 PG 兼容子集 | 教师无需安装数据库即可复现；同一套 Flyway 脚本可用于 PG |
| 用 Flyway 版本化迁移替代独立 `schema.sql`/`data.sql` | 一次执行、可重复启动、不丢数据，避免二次启动 DROP 重建 | 文档中说明「建表脚本 = V1，种子数据 = V2」 |
| JWT 不携带权限，每次请求从库加载 | 满足「权限修改后立即生效且不写死」的硬要求 | 每请求多一次用户/权限查询，课程规模可接受 |
| refresh token 存 HttpOnly Cookie + 数据库只存哈希 | 降低 XSS 窃取与数据库泄露风险 | 前端需 `withCredentials`，开发期用 Vite 代理避免跨域 |
| 未配置 `JWT_SIGNING_KEY` 时随机生成 | 仓库不得提交密钥，同时保证开箱即跑 | 重启后旧令牌失效，README 注明生产必须注入固定密钥 |
| 权限矩阵中的业务权限码先全部入库 | 权限目录与角色映射是设计基线，第二/三阶段直接复用 | 第一阶段接口只用身份/组织相关权限码 |
